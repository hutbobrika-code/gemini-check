# gemini-check

Telegram-бот, который следит, открываются ли Gemini, ChatGPT, Claude, YouTube и
другие площадки через узлы VPN-подписки и через арендованные прокси. Живёт
целиком в GitHub Actions, отдельный сервер не нужен.

## Как проверяется

Для каждого узла подписки поднимается временный Xray с локальным SOCKS. Конфиг
берётся из подписки живьём, вместе с её `routing` и `dns`, — проверяется ровно
то, что получает клиент. Прокси проверяются напрямую через HTTP-порт, SOCKS5 —
отдельно.

Через каждую точку:

- `ipinfo.io` — куда на самом деле выходит трафик;
- Gemini — веб-страница и API с заведомо неверным ключом. Где Gemini доступен,
  API отвечает `400 API key not valid`, где регион заблокирован — `403 User
  location is not supported`. Страница отдаёт `200` в обоих случаях, поэтому
  главный признак — API;
- площадки из [`services.json`](services.json). У ChatGPT и Claude геоблок
  тоже виден по API (`401` без ключа — регион разрешён, `403` — нет), у
  остальных — по коду ответа и тексту страницы.

Капчу Google бот ловит по цепочке редиректов: петля «капча → сайт → капча»
заканчивается на самом сайте и иначе выглядела бы безобидно.

| Статус | Значит |
|---|---|
| ✅ | всё открывается |
| 🚫 | точка жива, но какую-то площадку в этом регионе не пускают |
| ❌ | не отвечает: хост, туннель или площадка |
| ⚠️ | частично: капча, 429, API есть, а сайта нет |

## Что приходит в Telegram

Сам бот пишет только **об изменениях** и держит в группе одно такое сообщение:
новое заменяет прошлое. Изменение засчитывается, если продержалось две проверки
подряд, — одиночные таймауты не шумят.

```
🔴 Изменения · 18.09 15:42 МСК

⚠️ 🇩🇪 Германия · DE
    ❌ → ⚠️  Gemini (капча Google)
    ✅ → ❌  ChatGPT, Twitch

Без замечаний: узлы 11 из 18 · прокси 6 из 7
```

Команды:

- `/status` — полная картина: проблемные точки, рабочие точки и разбор по
  площадкам в раскрывающихся цитатах, файл со списком прокси;
- `/check адрес` — любой сайт через все точки;
- `/replaced` — история замен прокси.

## Прокси

Список берётся из API proxy-seller, так что купленное подхватывается само.
Адрес, который не отвечает или попал под капчу Google, бот сам отправляет
продавцу на замену — это бесплатно в рамках аренды. Покупать прокси бот не
умеет и не должен.

Новый адрес в Remnawave сам не попадает: бот присылает «было → стало», прописать
его нужно руками.

## Где работает

`listener.yml` запускает смену на пять часов: бот слушает команды и раз в час
проверяет точки. В конце смены состояние коммитится в `state/`, и смена
запускает следующую; ежечасный cron подхватит, если цепочка оборвётся.

После правки кода текущую смену нужно отменить — иначе она доработает свои
пять часов на старом коде.

## Настройка

Секреты репозитория (*Settings → Secrets and variables → Actions*):

| Секрет | Нужен | Что это |
|---|---|---|
| `TG_TOKEN` | да | токен бота |
| `TG_CHAT_IDS` | да | ID чатов через запятую; бот должен быть участником |
| `SUB_URL` | | ссылка на подписку; без неё проверяются только прокси |
| `PS_API_KEY` | | ключ API proxy-seller |
| `PROXIES` | | запасной список: `IP:ПОРТ@логин@пароль`, по строке на прокси |
| `GEMINI_API_KEY` | | настоящий ключ — тогда бот задаёт модели реальный вопрос |

## Локально

```bash
python3 -m unittest              # тесты
SUB_URL=... python3 bot.py --once  # одна проверка, отчёт в консоль
```

Нужен Xray в `bin/xray` (или путь в `XRAY_BIN`). Проверку с машины за VPN
лучше не считать эталоном: часть узлов оттуда не поднимается, хотя жива.

Вручную то же самое в Actions — воркфлоу «Самопроверка».

## Устройство

```
bot.py              смена: команды Telegram, проверки по расписанию
monitor/
  probes.py         пробы Gemini и площадок через готовый прокси
  nodes.py          подписка и Xray-туннели к её узлам
  proxies.py        прокси: список, проверка, автозамена
  report.py         тексты сообщений
  state.py          состояние между проверками и подтверждение изменений
  telegram.py       клиент Bot API
  http.py           запросы через curl
  model.py          точка и результат по площадке
services.json       какие площадки проверять и как
```
