# gemini-check

Бот в телеграме, который проверяет доступны ли Gemini, ChatGPT, Claude, YouTube и
ещё десяток площадок через узлы нашей подписки и через прокси. Работает в
GitHub Actions, сервер не нужен.

## Как работает

Под каждый узел подписки поднимается xray с локальным socks, конфиг берётся
прямо из подписки вместе с routing и dns (то есть ровно как у клиента). Прокси
проверяются напрямую, socks5 отдельно.

Через каждую точку:
- ipinfo.io, чтобы видеть куда реально выходит трафик
- Gemini. Главное тут api с неправильным ключом: если регион разрешён, он
  отвечает `400 API key not valid`, если нет, то `403 User location is not
  supported`. Сама страница gemini отдаёт 200 в обоих случаях, по ней не понять
- остальное из `services.json`. ChatGPT и Claude тоже смотрим по api
  (401 без ключа = регион ок, 403 = блок), остальные по коду ответа и тексту
  страницы

Капчу гугла ловим по цепочке редиретов (`/sorry/` в location), по конечному
адресу её не видно, там петля обратно на сайт.

Статусы: ✅ всё ок, 🚫 какую-то площадку в этом регионе не пускает,
❌ не отвечает, ⚠️ частично (капча, 429, api есть а сайта нет и т.п.)

## Что пишет в группу

Только изменения, и держит одно такое сообщение: новое удаляет старое.
Изменение засчитывается если повторилось две проверки подряд, иначе
случайные таймауты спамили бы каждый час.

Команды:
- `/status` - полная сводка + файл со списком прокси
- `/check адрес` - любой сайт через все точки
- `/replaced` - история замен прокси

## Прокси

Список берётся из api proxy-seller. Если прокси не отвечает или на нём капча,
бот сам отправляет его на замену (это бесплатно в рамках аренды). Покупать
бот ничего не должен, это только руками.

Новый ip в remnawave сам не попадает, бот присылает было/стало и его надо
вписать руками.

## Запуск

`listener.yml` запускает смену на 5 часов. В конце смены state коммитится в
`state/` и запускается следующая смена. Если поменял код, текущую смену надо
отменить, иначе она доработает на старом коде.

Секреты в Actions:

| | |
|---|---|
| `TG_TOKEN` | токен бота (обязательно) |
| `TG_CHAT_IDS` | id чатов через запятую (обязательно), бот должен быть в чате |
| `SUB_URL` | ссылка на подписку, без неё только прокси |
| `PS_API_KEY` | ключ api proxy-seller |
| `PROXIES` | запасной список, `IP:PORT@login@password` по строке |
| `GEMINI_API_KEY` | если есть настоящий ключ, бот спросит модель напрямую |

Локально:

```
python3 -m unittest
SUB_URL=... python3 bot.py --once
```

xray нужен в `bin/xray` (или путь в `XRAY_BIN`). С компа за впн проверять не
очень, часть узлов оттуда не поднимается хотя они живые. То же самое можно
запустить в actions через "Самопроверка".
